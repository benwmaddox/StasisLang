# Computation benchmarks - 2026-09-24

On this run, Stasis Cranelift AOT was faster than Rust Cranelift on 4 of 7 matched kernels: Fibonacci, sieve, partial sums, and Conway's Game of Life. It was about 7-14% slower on Mandelbrot, matrix multiply, and N queens. This is a measured result on one Windows host, not a general ranking of either language or backend.

The same Rust source compiled with LLVM was faster than Rust Cranelift on every kernel in this run. That supports code generation as one contributor to the earlier Stasis-Rust gap, but the Stasis and Rust implementations have different frontends and array storage.

*Each Stasis JIT process compiles before executing. The AOT and Rust binaries were built before timing. All columns include process startup and output.

## Conditions and limits

- Run timestamp: 2026-09-24 17:03:51 UTC
- Host: Microsoft Windows NT 10.0.26200.0; Intel(R) Core(TM) Ultra 9 185H
- Stasis: stasis 0.1.0
- Rust: rustc 1.100.0-nightly (6eeff9a52 2026-09-23)
- Rust flags: --edition=2021 -C opt-level=3 -C target-cpu=native -C panic=abort; -Zcodegen-backend=llvm|cranelift
- Method: 2 warmup launches, 10 measured launches per implementation, rotating order, median elapsed process time.

The Rust LLVM and Rust Cranelift binaries use the same source and nightly compiler; only the backend flag differs. They link the same prebuilt nightly standard library. Stasis uses fixed global arrays while Rust uses local vectors. The Rust Cranelift backend is a preview. Results varied between runs on this hybrid CPU; small differences are near parity.

A preliminary 300-generation Life variant produced different counts (Stasis 663, Rust 838), so the checked suite uses the 100-generation variant where both agree. The longer variant needs investigation before using it as performance evidence.
