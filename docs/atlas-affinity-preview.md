# Atlas affinity preview exporter

The exporter renders atlases from the exact native page inventory and baseline placements returned by stasis_gfx_sprite_atlas_query_v1. It sends that inventory and directed pair weights to stasis_dynload::atlas_placement::plan_atlas_affinity, then paints only the returned placements. Python does not choose sprite pages or reproduce the planner.

## Reproduce a named-game preview

Run from the StasisLang checkout after a JIT or AOT run has written a native snapshot through STASIS_ATLAS_SNAPSHOT_OUT and the compiler has produced its engine-bundle manifest v4.

One command: .\tools\run_atlas_affinity_preview.ps1 -Game RootbeerMaze3 -Snapshot .\artifacts\rootbeer-atlas-native.json -AotManifest .\artifacts\rootbeer.engine-bundle.json

The same command accepts SheepHerder or HamsterHavenTycoon. It expects the source projects in sibling directories of this checkout; pass -ProjectRoot when they live elsewhere. The wrapper writes under docs/evidence/task-623-atlas-affinity by default. The Python process needs Pillow and CairoSVG for PNG and SVG sources, and Cargo needs the normal workspace toolchain. CairoSVG is used only to rasterize original SVG assets at their native realized dimensions.

For compiler evidence, the standalone public-API utility can emit a fresh engine-bundle manifest: `cargo run --offline --manifest-path tools/atlas_aot_manifest_export/Cargo.toml -- D:\code\SheepHerder src\main.stasis D:\code\StasisLang\build\task623-sheepherder-aot`. It uses release reachability and writes `engine_bundle_manifest.json` under the selected output directory without modifying the game project. The current SheepHerder v4 manifest is incomplete because its transition analysis reaches an unbounded or dynamic loop; preview output must identify that and use the native bounded runtime histogram when available.

The exporter validates the native schema and applies the production bridge's page eligibility flags, compatibility checks, usable origins, allocation bytes, resident handles, extents, padding, and current positions. It sends every bridge-eligible page to the Rust planner at its exact native extent; 512×512 is the default affinity page extent, not a production restriction. Protected, dedicated, unsupported, or resident-blocked pages remain frozen at their native placements and retain their exact dimensions and allocation bytes in both output manifests and PNGs. Path matching uses the native normalized-path FNV-1a 64-bit hash plus logical dimensions; duplicate or ambiguous identity joins are rejected as compiler evidence.

A complete, finite AOT v4 transition summary is preferred. Every directed from_identity → to_identity edge must resolve to exactly one resident handle. If the manifest is incomplete or any edge is unmapped, the tool records the rejection and uses the exact directed runtime histogram from the same native snapshot when available. An explicit --curated-pairs file can be used only with --allow-illustrative; such output is marked curated-illustrative and is not accepted telemetry.

Outputs include unlabeled RGBA atlas PNGs at exact native page extents, 2000×900 contact sheets, and a JSON manifest with source hashes, the full page inventory, frozen-page reasons, placements, evidence provenance, and baseline/optimized planner metrics. Planner metrics cover only bridge-eligible pages; frozen page bytes remain in the full current/final memory accounting. Pages are reconstructed from source assets and exact positions; the query ABI does not return original texture pixels or reserved-header artwork, so those pixels remain transparent in the preview. The pair histogram is not used to infer native page-run or submission counts. GPU timing is reported as not-measured unless a supported host measurement is explicitly supplied.

## Native capture outcomes

The tracked [capture report](evidence/task-623-atlas-affinity/README.md) records the 2000×900 attempts and their exact limits. SheepHerder produced six native pages and 21 residents, but all pages were outside the bridge's plan-eligible set (`group_id=0`); the production Rust planner returned `empty_input`, leaving both baseline and candidate optimizer metrics null. Two 512×512 pages were observed, alongside the exact oversized extents; none was fabricated. RootbeerMaze3's 129-frame recording at 2000×900 reached the portrait app's unsupported-layout screen and emitted no valid native pair snapshot. HamsterHavenTycoon returned nonzero from `gameplay_config_valid()` before its first recorded frame. The separate 200×120 native fixture proves the query and planner path but is not an app performance measurement.

Runtime histogram rows are accepted only when native flag bit 0 (`PAIR_VALID`) is set and overflow bits 1 (`PAIR_OVERFLOW`) and 2 (`INVENTORY_OVERFLOW`) are clear. Accepted AOT v4 evidence must match the production limits exactly: 4096 rows, weight at most 1,000,000,000, zero omitted rows, and no unknown causes. The SheepHerder manifest is incomplete because it contains the cause `unbounded or dynamic for loop`; the report preserves that cause and uses its bounded runtime histogram for fallback evidence.
