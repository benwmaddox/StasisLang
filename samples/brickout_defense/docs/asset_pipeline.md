# Asset catalog and source fidelity

The recovered source at commit `7e7f04bfbce8417234435781127e4a17784341be` supplied 738 original asset files. They are preserved byte-for-byte in `assets/original/` and verified against `assets/original/asset_lineage.json`; the catalog loads the 25 static sprites and all 597 animation frames used by the game. The 42 unused label SVGs and 11 unused digit SVGs remain in the source archive unchanged, but text is rendered through current `TextRun` values.

`assets/asset_catalog.json` is the source of truth for the 622 registered images and frame tables. `tools/build_asset_catalog.py --write` regenerates the typed request dispatcher and animation ID tables; the default invocation verifies source hashes, contiguous IDs, dimensions, frame counts, and generated-file parity. The runtime catalog owns a single pending `ImageAsset`, publishes successful loads into an indexed `Sprite` owner array, and stops in an explicit error state if request, decode, or publish fails. The audio loader issues all six typed `AudioAsset` requests during boot and tracks their ready/failed states. Gameplay starts only after all 622 images, all three font sizes, and all six audio assets are ready and the background music starts looping successfully; any failed request, publish, or music start leaves the app on its explicit loading error state. The single-image loader bounds sprite decode work while the app shows monotone loading progress.

Android launcher resources are deterministic derivatives of the original art masters. `tools/build_launcher_icons.py` records exact master paths and SHA-256 values, composition geometry, alpha behavior, output sizes, and the adaptive icon foreground/background contract. The five legacy density icons keep the larger recovered composition; the adaptive foreground fits within Android's centered 66dp safe square on a 108dp layer and is checked against the central 72dp circle viewport. The generator also produces actual circle and p=4 squircle viewport previews using the same solid background and foreground layers referenced by the adaptive icon XML. Original masters are never overwritten, resized in place, or repacked. See [Android's adaptive icon guidance](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive) for the layer and safe-zone requirements.
